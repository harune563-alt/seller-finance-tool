# RCA — run d7cf82f6-3f64-4d20-ab05-248ebf82e97c (legacy-dev-2)

## Summary
Initial deploy failed at the **pull_source / prepare-build-context** phase (surfaced as the `build` step in `get_step_status`). The deployer tried to read the env files declared in the template's `config.yaml` `env_paths` and could not find `frontend/.env` in the pulled source.

## Exact error
```
prepare build context: read envs: read env file frontend/.env:
open /tmp/agent-env-...-/app/frontend/.env: no such file or directory
```
Step status: `build` = failed at 22:13:36; all later steps = "not run: an earlier deploy step failed".

## Root cause
- Template: `fastapi_react_mongo_shadcn_base_image` (farm, arm64, cloudflare frontend).
- No `config.yaml` override exists in GCS, so the build uses the platform-default farm config. That default declares `env_paths: [backend/.env, frontend/.env]`.
- `pull_source` reads every file in `env_paths` while assembling the build context. `frontend/.env` is **absent from the source**, so the read fails and the whole context prep aborts before any image build starts.
- Every farm React frontend is expected to ship a `frontend/.env` carrying at least `REACT_APP_BACKEND_URL`; its absence is the fault.

## Why this is NOT fixed by retry or by a manifest edit
- The error is deterministic (file not found), not a transient copy/wake blip — a plain `resume_pipeline` retry fails identically.
- Removing `frontend/.env` from `config.yaml` `env_paths` WOULD let `pull_source` pass, but the frontend build bakes `REACT_APP_BACKEND_URL` from that `.env` (the Dockerfile seds the prod BACKEND_URL into `/app/.env`). With no `.env`, the deployed frontend would have no backend URL and could not reach `/api/*` — a broken app, not a fix. So no manifest hack was applied.
- Could not reproduce in the eph sandbox: source access could not be prepared (the archive was never fully staged because pull_source aborted), and the sandbox has no secrets regardless.

## Fix (owned by E1 — source change in preview, then redeploy)
Create `frontend/.env` in the app source with at minimum:
```
REACT_APP_BACKEND_URL=<preview backend URL>
```
Use the same value the preview app uses (the standard farm preview backend URL). The deployer rewrites this to the production backend URL at build time automatically — the file just needs to exist with the key. After creating it, re-trigger the deploy.
